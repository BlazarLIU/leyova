# 中国 6 大电商平台业务模型差异调研

> 用途：为统一电商分析系统的平台差异化功能设计提供依据
> 原则：只写有公开出处的事实；找不到来源的标「待核实」；不编造数字

---

## 0. 一页速览

| 平台 | 核心经营单元 | 经营逻辑 | 核心付费工具 | ROI 口径关键词 |
|---|---|---|---|---|
| 淘宝/天猫 | 店铺 + SKU（货架） | 人找货：搜索 + 推荐 + 内容场 | 万相台无界版 | 总成交金额 / 花费（末次成交归因）|
| 京东 | 自营=采销单/SKU；POP=店铺+SKU | 自营是供货关系，POP 是平台服务关系 | 京准通 | 投产比（默认 30 天转化周期）|
| 拼多多 | 商品 + 拼团（团购单元）| 货找人的极致价格货架 | 商品推广 | 交易额/花费；新增结算投产比 |
| 快手 | 快手号 + 直播间 + 店铺 | 关注页私域为主、发现页公域补量 | 磁力金牛 | 当日总 ROI（含间接成交）|
| 小红书 | 笔记 + SPU + 买手/店播 | 内容种草 → 搜索决策 → 站内/站外成交 | 聚光/薯条/蒲公英/千帆 | 种草度量（AIPS + 小红星/小红盟）|
| 抖音 | 达人号/店铺 + 直播间 | 兴趣推荐分发（对照组）| 巨量千川 | 直播/短视频/货架归因 ROI |

## 1. 淘宝 / 天猫

### 1.1 核心经营单元
店铺 + SKU。淘宝可用个人身份开店，天猫必须企业主体（企业支付宝、商标/授权、保证金 + 技术服务年费、平台审核）。同一卖家可同时持有淘宝店与天猫店，但是**两个独立店铺**。

### 1.2 核心指标（生意参谋口径）

| 指标 | 定义 |
|---|---|
| 访客数（UV） | 店铺页/详情页被访问去重人数 |
| 浏览量（PV） | 被访问次数，多次累加 |
| 支付买家数 | 完成支付的去重买家人数 |
| 支付金额 | 通过支付宝支付金额，**未剔除事后退款** |
| 支付转化率 | 支付买家数 / 访客数 |
| 下单转化率 | 下单买家数 / 访客数 |
| 客单价 | 支付金额 / 支付买家数 |
| 商品动销率 | 支付商品数 / 店铺在线商品数 |
| 加购件数 / 收藏次数 | 商品行为指标 |
| DSR 三项 | 描述相符/服务态度/物流服务，**取最近 180 天** |
| 老访客 | 本次访问前 **6 天内**来访过店铺 |
| 同行平均/优秀 | 类目 60% / 90% 分位——分位值不是绝对值 |
| 父订单 / 子订单 | 父=一次付款主订单；子=商品×SKU 明细 |

**订单粒度**：淘宝是「父订单 + 子订单」双层结构，取数必须声明取哪一层。

### 1.3 ���量与投放
- 免费：手淘搜索、首页「猜你喜欢」、逛逛、订阅/关注、淘宝直播、拍立淘、类目频道、聚划算、问大家；站外淘宝客
- 付费：**万相台无界版**（2024-08-15 直通车/引力魔方/万相台停止服务，全面迁移）
- **关键点**：万相台（广告口径）与生意参谋（访客/支付口径）天然不一致，复盘必须先声明用哪个后台

### 1.4 特有对象
店铺层级、DSR 三评分（180 天滚动）、店铺综合体验分、淘宝客/淘宝联盟、聚划算会场、父/子订单结构

### 1.5 售后规则
- 2024 年跟进「仅退款」，2024 年 7-8 月松绑：**店铺综合体验分 ≥ 4.8** 不主动介入收货后仅退款
- 天猫基础承诺：7 天无理由退换货

### 1.6 与抖音最大差异
淘宝天猫**货架为主、内容为辅**——经营对象是店铺和 SKU；抖音**内容为主、货架为辅**，直播间时长和漏斗就是经营主线。

## 2. 京东（自营 + POP 混合）��� 全平台最特殊

### 2.1 两种模式

| 模式 | 谁经营 | 经营单元 | 商家角色 |
|---|---|---|---|
| **自营（采销）** | 京东采销 | **采销单 / SKU 供货** | 供货商：报供货价、送货入仓、开票结算 |
| **POP** | 第三方商家 | 店铺 + SKU | 商家：自己定价、发货、售后 |

**自营关键事实**：
- 京东采购部门直接采购到仓（**邀约式入驻**）
- 售价由京东定，商家基本无运营权
- 毛利口径：**(零售价 - 供货价) / 零售价**
- 账期：周结/月结/60 天结
- 发票：商家开增值税专票给京东

**POP 模式**（公开资料以 2017 年后为主）：
- **SOP**：商家自发货、自发开票，要求 12 小时内发货
- **FBP**：入京东仓，京东仓储+配送+收款+开票
- ⚠️ FBP/LBP/SOPL 各模式当前是否全部存续**待核实**

### 2.2 自营 vs POP 数据口径（系统设计重点）

| 维度 | 自营 | POP |
|---|---|---|
| 销售额口径 | 供货金额（采销额），**对供货商不是收入** | 成交金额归属商家 |
| 毛利 | 零售价-供货价，归京东 | 归商家，扣平台费用 |
| 库存归属 | 京东仓 | SOP 商家仓；FBP 京东仓 |
| 履约责任 | 京东配送 | SOP 商家；FBP 京东 |
| 结算 | 周/月/60 天 | 月结，月初对账 |
| 售后责任 | 质量问题商家担，否则京东担 | 商家全担 |

> **结论：必须按模式拆开，禁止跨 mode 加总 GMV。**

### 2.3 核心指标（京麦官方）

| 指标 | 定义 |
|---|---|
| 浏览量 / 访客数 | 页面访问次数 / 人数（当天去重）|
| **成交单量** | 用户付款订单量，**含先款和货到付款** |
| 成交客户数 | 付款用户数，含 COD，多笔去重 |
| 成交转化率 | 成交客户数 / 访客数 |
| **成交金额** | 付款总金额，**含先款与货到付款** |
| 客单价 | 成交金额 / 成交客户数 |

**「货到付款」是京东独有的大口径变量**——与纯在线支付平台不可直接比。

**店铺星级（2025-09 最新）**：
- 四维：客服咨询、物流履约、商品体验、售后服务
- 物流履约新增「**延迟发货单量**」减分项（超 48 小时）
- 客服：咚咚「无响应」会话纳入考核，时段 **9:00-23:00**
- 影响：搜索排序、商品数量资源、营销资格

### 2.4 投放
- **京准通**：搜索快车、推荐广告、智能投放、京东联盟、站外广告、合约广告
- 计费：CPC / CPM / CPD / CPS
- **投产比默认 30 天转化周期**，可切 15 天；区分**直接订单/间接订单**、直接订单金额/间接订单金额

### 2.5 售后规则（2024-02 POP 升级）
- 审核兜底 48h → **24h**
- 收货兜底 **24h**
- 退换场景收货处理兜底 3 天 → **24h**
- 寄出/揽件处理 10 天 → **7 天**
- 「直接拒绝售后」→「协商拒绝」；「强制关单」→「协商一致关单」

> 京东压力点是**履约与售后时效考核硬**，不是拼多多式仅退款。

### 2.6 与抖音最大差异
京东是**履约驱动的零售公司**（考核时效、履约率、售后速度）；抖音是**流量驱动的流量公司**（考核内容效率与时长漏斗）。京东的「自营」层在抖音体系里没有对应物。

## 3. 拼多多（社交货架电商）

### 3.1 核心经营单元
**商品 + 拼团**。经营主体是 SKU，但订单原子是「**团**」：拼单价与单独购买价并行，支付后进入「待分享/待成团」，达成团人数才进入标准订单流程。

### 3.2 ���团如何影响订单指标（系统设计重点）

1. **「支付」≠「成交」**：支付后是「待成团」，未成团自动退款，需单独统计成团转化率
2. **售后指标分母是「已成团订单」**：
   - 退款率 = 30天退款成功订单数 / 30天**已成团**订单总数
   - 介入率 = 30天平台介入订单数 / 已成团订单总数
   - 纠纷退款率、品质退款率同理
3. **团长/团员退款权限不同**：2 人团团长未成团期间不能直接退款，24h 未拼成自动退
4. **结算口径**（2025-09 新增 10 项指标）：
   - 结算金额 = 总交易额 - 退款交易额
   - 结算笔数 = 成交笔数 - 退单笔数
   - **部分退款只剔除对应金额，且该单不计入退单笔数**
5. **净成交出价**（2025-01）：净成交 = 剔除秒退订单（支付后 1 小时内且当日 23:59:59 前退款、商家未发货）

> **拼多多所有核心指标要区分「成团口径 / 结算口径 / 净成交口径」，只存一个 GMV 就是错的。**

### 3.3 流量与投放
- 免费：搜索、推荐信息流、**拼团分享裂变**、秒杀/百亿补贴、多多视频、多多直播
- 付费：**商品推广**（2024-07 全站推广+标准推广下线合并）
- **投产比 14 天归因**；新增**结算投产比**（结算金额/花费）

### 3.4 特有对象
拼团/团（待成团、拼团中、已成团）、免拼权益、店铺领航员 + 成长层级 + 体验星级（三套并存）、百亿补贴/限时秒杀、多多进宝（CPS）

### 3.5 售后规则
- 「**仅退款**」首创者（2021），仅退款流程适用**所有订单**
- 2025-05-15 起延迟发货认定改为「未在时限内完成发货及揽收」，普通商品默认 **48 小时**
- 虚假发货赔付 25% → 5%

### 3.6 与抖音最大差异
拼多多是**纯货架 + 价格 + 社交裂变**，无内容分发，订单多一层「团」前置状态；抖音是内容分发驱动，有完整时长/互动/漏斗。

## 4. 快手（直播电商）

### 4.1 核心经营单元
**快手号（主播/达人/店铺）+ 直播间 + 快手小店**。经营单元是「人」：主播号承载粉丝资产，直播间是成交场。

### 4.2 核心指标（磁力金牛官方白皮书）

| 指标 | 公式 |
|---|---|
| **当日总成交订单金额（全站 GMV）** | 直接成交 + **间接成交** |
| 直接成交订单金额 | 用户直接下单成交 |
| **间接成交订单金额** | 点击广告未直接转化，**当天内**通过关注/搜索/购物车/个人主页/橱窗再次触达同店/同号并成交 |
| **当日总 ROI** | 当日总成交订单金额 / 花费 |
| **净成交 ROI** | 剔除**下单后 1 小时内退款** |
| **7 日累计 ROI** | 7 日累计 GMV / 花费 |
| **调控涨粉 ROI** | 推广带来的关注用户在 1/7/15/30 日的总成交 / 调控花费 |
| GPM | 千次曝光转化价值（2025 纳入排序）|

**快手官方明确说明**：磁力金牛（投流口径）与生意通（经营口径）**天然对不上，不建议直接对比**：
- 归因时间：金牛按广告触达日期，触达后 **24 小时**；生意通按实际支付时间
- 成交渠道：金牛不区分下单渠道；生意通按实际渠道归因
- 账户/商品：金牛只统计单账户；生意通统计店铺所有成交

### 4.3 流量结构（本质差异）
- **公私域双轮循环**：发现页（公域）拉新 → 沉淀粉丝 → 关注页（私域）复购
- 券商研报称「60%+ 交易来自关注页」（**第三方口径，待核实**）
- 付费：**磁力金牛**（电商投流）、磁力聚星（达人）、粉丝头条（内容加热）、磁力智投
- 2025 排序机制：ECPM + **GPM** + 内容互动率 + 播放/停留时长

### 4.4 特有对象
- **粉丝团/购物团**：随购物点赞分享累积**亲密度**升级，梯度权益
- **关注页私域**：独立流量与成交来源
- **间接成交**：官方一级指标，快手独有
- **调控任务**：带独立涨粉 ROI 序列

### 4.5 与抖音最大差异
快手是**「先关注后成交」的私域电商**——发现页拉新、关注页复购；抖音是**「先成交再沉淀」的公域兴趣电商**。
一句话：**快手算「一个粉丝三年值多少钱」，抖音算「一次曝光值多少 GMV」。**

## 5. 小红书（内容种草电商）

### 5.1 核心经营单元 —— 不是店铺
官方 **NPL 经营方法论**：
- **N（note 笔记）**：形成基础认知、激发潜在需求
- **P（people）**：借助**群聊**把粉丝转化为用户资产
- **L（直播）**：锁定高意向用户、放大成交

商家后台是**千帆**。定位演进：买手电商 → 生活方式电商 → 「卖好货就来小红书」。

### 5.2 核心指标
- 官方核心逻辑：**「LTV × 用户数」**，不是「访客×转化率×客单价」
- 千帆看板维度：流量、商品、**笔记**、直播、**搜索**、店铺、服务、营销——**「笔记」「搜索」是独立维度，其他平台没有**
- 平台自披露：老客购买金额贡献占比 81%、平均复购率 32%（**平台自披露，非行业基准**）

### 5.3 流量与投放
- **搜索是第一入口**：链路「发现浏览 → 搜索决策 → 内容/直播转化 → 评价反馈」
- 官方口径：「有购买意图的搜索占比 25%」
- 第三方称「70% 成交相关行为来自搜索」——**与官方口径不同，勿混用**

| 工具 | 是什么 |
|---|---|
| **聚光** | 一站式广告投放平台，搜索+浏览两场景，支持 SPU 定向 |
| **薯条** | 原生内容加热，**不带广告标识** |
| **蒲公英** | 达人合作平台 |
| **千帆（推广）** | 电商商家一体化推广 |
| **灵犀** | 选品、调研、卖点投放 |
| **小红星/小红盟/小红链** | 种草联盟跨平台归因（淘宝/京东等）|

- **ROI 无统一口径**：过程用 **AIPS 人群资产模型**，结果用种草联盟跨平台归因，种草 ROI 拆互动/搜索/进店三维

### 5.4 特有对象
- **笔记**：核心资产，非商品
- **群聊**：私域承接唯一形态
- **买手（主播）**：核心供给角色
- **SPU 颗粒度**：聚光定向与千帆商品分析都以 SPU 而非店铺
- **站外成交**（红猫/红京/红美）：→ **GMV 天然有站内/站外两个口径**

### 5.5 与抖音最大差异
小红书**没有「店铺流量」的单极概念**：核心是「**笔记 × 搜索 × 人（群聊/买手）**」，且允许成交在站外；抖音核心是「**直播间/短视频 × 推荐算法**」，成交闭环站内。
**抖音算漏斗，小红书算人群资产和复购。**

## 6. 横向对比矩阵

### 6.1 核心经营单元
| 平台 | 一级实体 | 二级实体 | 分析主体 |
|---|---|---|---|
| 淘宝/天猫 | 店铺 | SKU / 父子订单 | 店铺、商品 |
| 京东自营 | 采销单 | SKU 供货 | 采销单、SKU |
| 京东 POP | 店铺 | SKU / 订单 / 服务单 | 店铺、商品 |
| 拼多多 | 商品 | **团**（待成团/已成团）、SKU | 商品、团 |
| 快手 | 快手号 | 直播间、店铺、**粉丝团** | 快手号、直播间 |
| 小红书 | **笔记** | SPU、买手、**群聊**、直播间 | 笔记、SPU |
| 抖音 | 达人号/店铺 | 直播间、短视频、商城 | 直播间、短视频 |

### 6.2 「成交」叫什么
| 平台 | 叫法 | 分母口径 | 特有指标 |
|---|---|---|---|
| 淘宝/天猫 | 支付金额、支付买家数 | 访客数 | 支付转化率、加购件数、DSR |
| 京东 | 成交金额、成交客户数（**含货到付款**）| 访客数 | 店铺星级四维、延迟发货单量、咚咚响应 |
| 拼多多 | 交易额 / 结算金额 / 净成交 | **已成团订单数** | 询单转化率、介入率、结算投产比 |
| 快手 | 全站 GMV（直接+间接）| 曝光次数 | **间接成交**、净成交 ROI、涨粉 N 日 ROI |
| 小红书 | 站内成交 / 站外成交 | 笔记曝光/搜索曝光 | 笔记互动率、搜索来源占比、AIPS |
| 抖音 | 直播间/货架 GMV | 曝光 | 分钟级漏斗、GPM |

### 6.3 投放归因
| 平台 | 工具 | ROI 名称 | 归因窗口 | 含间接成交 |
|---|---|---|---|---|

## 7. 关键设计结论（最核心的 5 个差异化维度）

### ① 成交口径（GMV 定义本身不统一）— 最高优先级
淘宝：支付金额（未剔退款）；京东：成交金额（**含货到付款**）；拼多多：交易额/结算金额/净成交**三套**；快手：总成交（**含间接**）/净成交；小红书：**站内 vs 站外**。

**设计要求**：
- 指标字典必须带 `amount_type ∈ {gross_paid, gross_settled, net_settled, indirect_included, offline_cod_included}`
- 必须带 `attribution_window`
- **跨平台对比只能在同一 amount_type 上做**
- 页面必须显式标注当前口径

### ② 经营单元与分析主体（entity 模型）
**设计要求**：「通用实体 + 平台扩展实体」
- 核心表：`shop / product / order / traffic_source`
- 扩展表：`group_buy（拼团）` / `note（笔记）` / `live_room（直播间）` / `purchase_order（采销单）` / `service_ticket（服务单）`
- **不要把团、笔记硬塞进订单表**

### ③ 流量来源目录体系（source taxonomy 不可复用）
淘系「淘内免费/付费/淘外」+ 搜索/首猜/逛逛/订阅/直播；京东「PC/App/微信商城/QQ商城/M站」+ 四级渠道；拼多多搜索/推荐/**团页面**/分享裂变；快手**发现页/关注页**；小红书**推荐/搜索/笔记/群聊**。

**设计要求**：统一 L0-L1-L2 三级通用中间层（自然搜索/推荐/私域/内容/付费/站外），平台原始来源用**可配置映射表**挂到通用层，**保留 raw_source**，映射可回归验证。

### ④ 推广归因模型（决定 ROI 能否横向比）
归因窗口：京东 30 天 / 拼多多 14 天 / 快手 24h + 1/7/15/30 日 / 淘宝末次成交 / 小红书跨平台。

**设计要求**：
- 投放表固定为 `(platform, tool, campaign, spend, attributed_gmv, attribution_window, attribution_type, direct_gmv, indirect_gmv, net_gmv)`
- **不允许只存一个 ROI**
- 接受事实：**广告后台与商家后台的数永远不一致**（快手官方明说），系统要内置「双源对账」视图而不是试图对齐

### ⑤ 履约与售后责任模型（决定订单状态机与 SLA）
京东：双责任方 + 24h 兜底 + 48h 延迟发货；拼多多：**成团前置状态** + 全订单仅退款 + 48h 发货揽收；淘宝：体验分驱动；快手/小红书较轻（待核实）。

**设计要求**：
- 订单状态机可插拔（拼多多多「待成团」态）
- 售后指标分母由平台规则决定（拼多多用已成团订单数）
- **SLA 必须按平台配置，不能硬编码 48 小时**
