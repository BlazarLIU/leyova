## 0. 一分钟结论

| 问题 | 结论 |
|---|---|
| 模块/分组是否贴近真实业务 | **骨架对、颗粒度错**。9 大工作面（今日作战/场次/货盘/流量投放/履约售后/内容达人/人与钱/数据/系统）方向正确；但「场次」与「复盘」被拆到两套导航，真实业务里是一条链 |
| 切平台后分组/模块能否对应显示 | **不能**。平台切换只影响前端 22/90 条菜单项，后端 0 过滤；前端**从不发送** `x-leyova-platform`；能力矩阵 198 行 0 项 `is_applicable=false`；六平台 `supportedModules` 命名与 `system_modules.code` 不一致 |
| 每个功能真实场景能否用 | **约 1/3 可用**。122 页面中：真实接后端且数据可读约 45 页；半可用（接口在、数据空/降级）约 40 页；纯静态或硬编码 ≥ 10 页；另有 54 个页面静默吞错 |
| 是否有多余/重复功能 | **有**。双导航（经典 90 项 + AI-Ops 30 项）同页挂两次；`/review/*` 全部重定向到 `/ai-ops/review/*`；AI-Ops 30 项中 5 项纯硬编码、9 项走带编造兜底的数据层 |
| 功能关系图谱 | 见 `05-RELATIONSHIP-GRAPH.md`（数据主键是「场次」，但 AI-Ops 与经典系统各画一套） |
| 改进计划 | 见 `06-IMPROVEMENT-PLAN.md`（P0 11 项 / P1 13 项 / P2 7 项 / P3 5 项，每项带证据、改法、验收） |
| 能否达到 5 项 AI 标准 | **部分**。规则引擎+可追溯契约真实存在且已跑 3648 次；但 LLM 关闭、向量库无、数字人/ASR/剪映/千川均无代码、提示词无版本管理 → 5 项中 1 项基本达标、1 项半达标、3 项未达标。见 `07-AI-CAPABILITY-GAP.md` |

**一句话**：这是一套「业务骨架真实、数据链路半通、AI 外壳超前」的系统；当前最大风险不是缺功能，而是**界面看起来有、点进去数据是假的或空的，且错误被静默吞掉**。

## 2. 审计方法（可复现）

1. **外部业务基准先行**：先按代运营真实作业链（T-7 → T+2）建立 13 条必备能力与 8 条伪需求标尺（`_evidence/10-business-baseline.md`），再拿标尺量系统，而不是拿菜单当业务。
2. **运行时实测**：登录 13 个账号 → 13 个只读端点 × 9 账号的状态码矩阵；6 平台请求体比对；匿名基线；无效载荷写探针（必然 4xx，不落库）。
3. **数据层直查**：243 张表的行数、0 行表清单、关键表的分布查询（只读 SQL）。
4. **代码静态核对**：导航、权限、页面→接口台账、假数据扫描、外部能力关键词检索。
5. **对比前序报告**：Gemini 23 条、dsh 10 篇，逐条用本轮证据裁定「成立/部分成立/已变化/推翻」。

复现脚本：`_evidence/reproduce.sh`（只读命令集）。
